# Screenshot set

Every PNG in this directory is generated by
[`frontend/tests/screenshots/capture.spec.ts`](../../frontend/tests/screenshots/capture.spec.ts)
and committed so the docs (root README, hub) can reference a trustworthy,
current app surface. Nothing here is hand-edited or hand-shot.

Notes on what you will (and won't) see:

- **Every capture is the single warm ink theme** (June's
  [`warm-theme-unification-spec.md`](../design/warm-theme-unification-spec.md)):
  `bg-ink-bg` page, `bg-ink-surface` cards/nav, clay CTAs. There is no light
  mode and no toggle anymore; wizard step panels are the deliberate paper
  surface (`bg-paper`, stone text) that previews the printed card.
- **Review captures show an amber "This photo may print soft at 6×4″" banner.**
  That is the D1 low-resolution warning working as designed — the e2e fixture
  photo (600×400) is below the print minimum. It is expected; do not "fix" the
  banner by swapping fixtures.
- **Card faces render clean.** Since ISSUE-0123 the preview hard-hides the
  inactive face once the flip settles, so captures show no mirrored
  bleed-through even in headless Chromium (which ignores
  `backface-visibility` under compositing).
- The wizard data in every shot comes from the mocked API in
  [`frontend/tests/e2e/helpers.ts`](../../frontend/tests/e2e/helpers.ts) — no
  real backend, no real PostGrid, nothing ever mails.

## Regenerating

One command per step, all explicit (no magic servers):

```bash
cd frontend
pnpm build                              # 1. production build of the app
pnpm preview --port 5196 --strictPort   # 2. serve the built app (keep running)
E2E_BASE_URL=http://localhost:5196 pnpm capture   # 3. run the capture spec
```

- `pnpm capture` runs `playwright test capture.spec` (Playwright's desktop and
  mobile projects both execute it; each test pins its own viewport, so output
  is project-independent).
- Setting `E2E_BASE_URL` tells the Playwright config you own the server — it
  will not spawn a dev server on 5173 in that case.
- After the run, `git status docs/screenshots` shows exactly which PNGs
  changed; commit them alongside whatever UI change altered the surface.
