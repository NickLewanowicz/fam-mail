## Findings (ranked)

### P1

**F1. Horizontal overflow is app-shell-wide; culprit is the fixed-width nav cluster** — `src/components/layout/AppShell.tsx:43-108`
Right cluster (theme toggle + History + PostGridModeBadge + New + avatar) measures a fixed ~289px wide; with the logo the row bottoms out at ~407px regardless of viewport. Probe output: `docRight=407` at 375/390/320 on dashboard, wizard Review, and history — matches audit (+16/+17 @390) and spec failures (+29..+35 @375). Breaks M1 on every page and fails the e2e gate. It also undermines every later animation (fixed bars, bottom tab bar) that assumes a non-scrolling shell.
*Direction:* make the nav cluster wrap/shrink (<sm hide labels, collapse History+New into the planned bottom tab bar per #106); root-fix in AppShell, not per page. Supersedes the per-step fix direction in `ISSUE-0102`. Filed as ISSUE-0107.

**F2. 7 unit tests fail whenever `VITE_API_URL` is set — suite is not hermetic** — `vitest.config.ts`, `src/utils/apiConfig.ts:9`, `src/utils/api.test.ts:170`, `src/services/authApi.test.ts`
`frontend/.env` (git-ignored, staged-instance config: `VITE_API_URL=http://localhost:8485`) is loaded by Vitest, so `API_BASE_URL` becomes `http://localhost:8485` and every test asserting a relative URL (`'/api/postcards'`, `'/api/auth/...'`) fails. Gate 1 is red in the primary dev environment while CI stays green — a lying signal. `apiConfig.ts`'s comment also claims default port 8484 while `.env`/backend use 8485.
*Direction:* pin the env in vitest config (`test: { env: { VITE_API_URL: '' } }`) or assert against `API_BASE_URL` in the tests; fix the port comment. Filed as ISSUE-0108.

**F3. History "Again" prefills a mangled recipient and forces country = US** — `src/pages/HistoryPage.tsx:84`, `src/pages/CreatePage.tsx:48-55`, backend `routes/postcards.ts:130`
The history API returns `recipientAddress` as one display string (`"812 Maple Avenue, Portland, OR 97205"`). "Again" stuffs that whole string into `addressLine1`, blanks city/state/ZIP, and `CreatePage`'s prefill hard-codes `countryCode: 'US'` even when the original card went to CA/GB, then jumps to step 4 with the country selector locked. A user who re-fills just the blanks and sends mails a card with a comma-glued street line and the wrong country — real-money risk (mock mode tonight masked it).
*Direction:* return a structured address from the history endpoint (or persist one) and pass a full `Address` in `location.state`, preserving the original `countryCode`; never force 'US'. Filed as ISSUE-0109.

### P2

**F4. Dead/throw-prone country normalization in address validation** — `src/components/wizard/AddressStep.tsx:60-61`
`const country = (addr.countryCode || 'US').toUpperCase()` then `const country_ = country === addr.countryCode ? addr.countryCode : addr.countryCode.toUpperCase()` — if `countryCode` is ever undefined (legacy draft JSON), the second line throws inside the submit handler (no boundary for event handlers; the button just appears dead). Unreachable through the current UI, but it's the send path.
*Direction:* delete line 61 and use `country` — one line, removes both the latent crash and the confusion.

**F5. Recent-recipient chips can silently contradict the locked country** — `src/components/wizard/AddressStep.tsx:135` vs `:159-162`
Clicking a chip does `setForm({ ...EMPTY_ADDRESS, ...r })`, keeping the chip's `countryCode`; with a wizard country chosen, the Country field is a locked read-only display of the *wizard* country. A CA chip under a US wizard shows "United States" while validation and the sent payload use CA — same mismatch class as F3.
*Direction:* when `countryCode` prop is set, force `form.countryCode` to it (or show the chip's real country and let it win).

**F6. Inline address form: lying required-marker, no cancel, live-propagating edits** — `src/components/postcard/InlineAddressForm.tsx:84` vs `:32-42`, `:25-30`
"Apt / Suite" renders a red `*` but `handleDone` doesn't validate it (AddressStep marks the same field "(optional)"). There is no Cancel/revert — every keystroke calls `onAddressChange` to parent state, so closing the panel (or switching steps, which force-closes editors via `PostcardPreview.tsx:52-55`) keeps whatever partial garbage was typed.
*Direction:* drop the asterisk; add Cancel that restores the entry state; only commit validated data on Done.

**F7. Inline editors inside the postcard back are sub-16px with no inputmode/autocomplete** — `InlineAddressForm.tsx:44-49,72-100` (10–11px inputs), `InlineMessageEditor.tsx:233` (13px textarea)
Focus-zoom on iOS plus precision-tap targets inside a scaled card; extends `ISSUE-0104` (M3) which currently counts only the AddressStep input. The palette swatches are 24×24 (`InlineMessageEditor.tsx:196`) — part of #103's M2 family.
*Direction:* bump to ≥16px on touch breakpoints, add `inputmode`/`autocomplete`; consider opening the editors in a bottom sheet (M6) instead of inside the card.

**F8. Dashboard draft cards: keyboard trap on Delete/Export + hover-only Delete** — `src/pages/DashboardPage.tsx:139` vs `:184-196`
Card `onKeyDown` navigates on Enter/Space; Delete/Export stopPropagation only on *click*, so keyboard Enter on those buttons bubbles first and navigates to the draft editor instead of deleting/exporting. Delete is also `opacity-0 group-hover:opacity-100` (`:192`) — permanently invisible on touch.
*Direction:* in the card handler, ignore events whose target is an interactive descendant (or check `e.target === e.currentTarget`); always show row actions on coarse pointers.

**F9. Mobile wizard bottom toolbar clips its own buttons on notched phones** — `src/pages/CreatePage.tsx:453-464`
Container is `fixed … h-16` (64px) with `pb-[env(safe-area-inset-bottom)]`; on a 34px-inset iPhone the content box is 30px tall for `h-10` (40px) buttons — buttons overflow the blurred bar. (M5 will replace this bar; keep the math in mind for R3.)
*Direction:* drop fixed height — `min-h-16 h-auto pt-2 pb-[max(env(safe-area-inset-bottom),0.5rem)]`.

**F10. responsive.spec is flaky on mobile-dashboard overflow** — `tests/e2e/responsive.spec.ts:15-23`
Run 1: +32 FAIL; run 2 (same instance, no retries configured locally): PASS. Likely races the async drafts fetch / hero animation before measuring. Once F1 lands, assert after network-idle + `prefers-reduced-motion` or settle wait; consider enabling local retries.
*Direction:* settle-then-measure; keep CI retries as backstop, don't rely on them.
